## Summary

Implement `read_imap` so `type: imap` returns one row per message from a
mailbox folder. Registration, the `imap` credential validator, and
read-only `register_io_type` already exist. This CIP fills the fetch:
stdlib `imaplib`, header-only `BODY.PEEK`, a pandas DataFrame.

**Which requirements does this CIP address?** REQ-0001.

## Motivation

lynguine CIP-0019 shipped `register_io_type` and left the first external
plugin as follow-on work. This repository already declares `type: imap`.
`read_imap` still raises `NotImplementedError` after binding
`credential_value`. Until the fetch exists, flows cannot use a live
mailbox as allocation or input.

## Detailed Description

### Layering

lynguine fetches the CIP-0005 secret named by `credential:` and injects
it as `details["credential_value"]`. This package never calls
`CredentialManager`. The stored payload is:

```yaml
host: imap.example.org
user: inbox@example.org
password: "..."
```

The validator already requires those three non-empty strings.

### YAML (this package)

```yaml
plugins:
  - lynguine_imap

input:
  type: imap
  folder: INBOX
  credential: my_mail
  index: message_id
```

Optional keys on the item:

| Key | Default | Meaning |
|-----|---------|---------|
| `folder` | `INBOX` | IMAP mailbox to `SELECT` |
| `mailbox` | — | Alias for `folder` (lynguine CIP-0019 used this name). If both are set they must be equal |
| `limit` | none | Positive integer; keep the highest UIDs (newest on typical servers) |
| `ssl` | `true` | `IMAP4_SSL` vs plaintext `IMAP4` |
| `port` | `993` if ssl, else `143` | TCP port |

`index:` is lynguine `finalize_data`, not this reader.

### Row grain

One row per message UID. Columns, in order:

| Column | Source |
|--------|--------|
| `uid` | IMAP UID (string) |
| `message_id` | `Message-ID` header |
| `subject` | `Subject`, MIME-decoded |
| `from` | `From`, MIME-decoded |
| `date` | `Date` header as received (RFC 5322 text, not parsed) |

No body, no flags, no labels in v1. Bodies stay a CIP-0013 document
problem once a path or bytes exist.

### Protocol choices

- stdlib `imaplib` only. No extra vendor SDK.
- `SELECT` with `readonly=True`.
- `UID SEARCH ALL` then `UID FETCH` of
  `BODY.PEEK[HEADER.FIELDS (SUBJECT FROM DATE MESSAGE-ID)]`.
  `PEEK` so unseen mail stays unseen.
- SSL on port 993 by default. Plaintext is opt-in (`ssl: false`) for
  local test servers, not a silent fallback.
- Login failures name host and user, never the password.
- Missing folder: error includes the folder name.
- Empty folder: empty DataFrame with the five columns.

`connect` is a keyword-only argument on `read_imap` for tests. YAML
cannot inject it.

### Out of scope

- Gmail API / `google_oauth` (a later `type: gmail` can reuse CIP-0005
  `google_oauth`; this type is IMAP)
- Write-back (move, flag, append)
- Search criteria other than `ALL`
- Message bodies or attachments
- IDLE / push

## Implementation Plan

1. Split validator and reader out of `__init__.py`.
2. Implement `connect_imap` + UID header fetch.
3. Parse headers into the five-column frame.
4. Mocked tests: empty folder, headers, MIME subject, limit, readonly
   peek, missing credentials, folder errors. No network.

## Backward Compatibility

The plugin form (`type: imap`, `credential_type="imap"`, no writer) is
unchanged. Flows that already import the package will start receiving a
frame instead of `NotImplementedError`.

## Testing Strategy

- Fake IMAP client in unit tests (login / select / uid / logout).
- Direct `read_imap(..., connect=fake)`; no sockets.
- Assert `readonly=True` and `BODY.PEEK` in the FETCH spec.
- Keep existing registration tests.
- CIP-0005 local storage: `EncryptedFileCredentialProvider` in a temp
  directory and `EnvironmentCredentialProvider`. `read_data` on the
  example YAML (`type: imap`, `credential: my_mail`) must decrypt, bind
  `credential_value`, and login on a fake `IMAP4_SSL`. The `.cred` file
  must not contain the plaintext password. No network.
