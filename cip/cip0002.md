# CIP-0002: Microsoft IMAP XOAUTH2 in the plugin, not in lynguine

> CIPs describe HOW to achieve requirements (WHAT).
> Implements [REQ-0002](../requirements/req0002_oauth2-imap.md).
> Keeps [REQ-0001](../requirements/req0001_imap-message-table.md) for password IMAP.

> Hex numbers are per-repository. This is **lynguine-imap** CIP-0002.
> Secret storage is **lynguine** CIP-0005 / CIP-001A. The IO hook is
> lynguine CIP-0019. None of those CIPs grow an OAuth client.

## Summary

Add an explicit OAuth2 connect path to `type: imap` so Exchange Online
(Cambridge `@cam.ac.uk` and similar) can authenticate with SASL
`XOAUTH2`. Password `LOGIN` stays. MSAL, device-code sign-in, and
`AUTHENTICATE XOAUTH2` live in this package. lynguine only stores and
returns the named dict.

**Which requirements does this CIP address?** REQ-0002 (primary).
REQ-0001 remains the table contract.

## Motivation

CIP-0001 implemented header fetch behind IMAP `LOGIN` and a CIP-0005
payload `{host, user, password}`. That is correct for a classic IMAP
server and for Gmail **app passwords**.

University of Cambridge mail is Exchange Online. UIS documents:

- IMAP host `outlook.office365.com`, port 993, SSL/TLS
- Username `CRSid@cam.ac.uk`
- Authentication **Modern (OAuth)** — not `LOGIN`

Microsoft retired basic auth for Exchange Online IMAP. Storing a Raven
password and calling `client.login()` fails. The gap is protocol, not
storage: lynguine CIP-001A already persists named dicts and keeps
`lynguine-cred` offline.

Putting `msal` in lynguine would repeat the `gsheet` dependency mistake
(lynguine CIP-0019). The plugin already registers `credential_type="imap"`.

## Detailed Description

### Layering (do not move)

```
lynguine CIP-001A / CIP-0005          this package
────────────────────────────          ──────────────────────────
master key (OS keyring)               MSAL public client
encrypted named dict                  device-code / MFA once
lynguine-cred set/get (no network)    AUTHENTICATE XOAUTH2
credential: key in YAML               BODY.PEEK headers (CIP-0001)
```

YAML is unchanged:

```yaml
plugins:
  - lynguine_imap

input:
  type: imap
  folder: INBOX
  credential: cambridge_mail
  index: message_id
```

Host, tenant, client id, and tokens are **in the stored credential**,
not in the interface.

### Two explicit credential forms

`auth` names the IMAP SASL method. Do **not** infer OAuth from
`outlook.office365.com` (explicit infrastructure).

**LOGIN** (CIP-0001, default when `auth` is omitted):

```json
{
  "host": "imap.example.org",
  "user": "inbox@example.org",
  "password": "..."
}
```

Equivalent: `"auth": "login"` with the same three fields.

**XOAUTH2**:

```json
{
  "auth": "xoauth2",
  "host": "outlook.office365.com",
  "user": "crsid@cam.ac.uk",
  "client_id": "<entra-public-client-id>",
  "tenant": "organizations",
  "refresh_token": "..."
}
```

| Field | Required | Notes |
|-------|----------|--------|
| `auth` | yes for this form | Exactly `xoauth2` |
| `host` | yes | UIS: `outlook.office365.com` |
| `user` | yes | `CRSid@cam.ac.uk` |
| `client_id` | yes | Operator-registered Entra **public** client. Not a Thunderbird or Outlook id shipped in this repo |
| `tenant` | yes | Directory id, `organizations`, or `common` |
| `refresh_token` | yes after bootstrap | From device-code; never YAML |
| `scope` | no | Default `https://outlook.office.com/IMAP.AccessAsUser.All` plus `offline_access` |
| `password` | must be absent | Mixing LOGIN and XOAUTH2 is an error |

The `imap` validator accepts **exactly one** form. Unknown `auth`
values fail.

### Connect

`connect_imap` (or a thin wrapper used by `read_imap`) branches on
`auth` after `_credential()`:

1. Open `IMAP4_SSL` (default port 993).
2. **login:** `client.login(user, password)` as today.
3. **xoauth2:** MSAL `acquire_token_by_refresh_token` → SASL XOAUTH2
   string → `client.authenticate("XOAUTH2", lambda: payload)`.
4. Then CIP-0001 `SELECT` / `UID SEARCH` / `BODY.PEEK`.

SASL payload (Microsoft):

```
base64("user=" + user + "\x01auth=Bearer " + access_token + "\x01\x01")
```

Failures name host and user, never the token. Missing `msal` on an
`xoauth2` credential raises a clear install extra error, not an IMAP
error.

Access tokens are short-lived and **not** stored. Each read refreshes
from `refresh_token`. If Microsoft returns a new refresh token, persist
it with `set_credential` for that key (see write-back below).

### Bootstrap command (plugin, not lynguine-cred)

lynguine CIP-001A: `lynguine-cred` has **no network** and no IMAP.
Interactive Microsoft sign-in is this package:

```
python -m lynguine_imap.login --name cambridge_mail \
  --host outlook.office365.com \
  --user crsid@cam.ac.uk \
  --client-id <id> \
  --tenant organizations
```

Behaviour:

1. MSAL public-client device code (or auth-code + local redirect if
   device code is blocked).
2. Operator completes Cambridge MFA in the browser.
3. `set_credential(name, payload, credential_type="imap")` via CIP-001A
   so the dict lands in `~/.lynguine/credentials/`.
4. Print the key name, not the tokens.

Poetry script optional: `lynguine-imap-login`. Extra: `oauth`
(`msal`). LOGIN-only installs do not need `msal`.

### Entra app (operator, not code)

The operator registers a **public client** in Microsoft Entra:

- Delegated permissions: `IMAP.AccessAsUser.All` (Office 365 Exchange
  Online) and `offline_access`
- Device code and/or mobile/desktop redirect
- Admin consent if the Cambridge tenant requires it

This repository does not ship a client id, does not impersonate
Thunderbird, and does not automate admin consent.

Cambridge values (documentation only, not defaults in code):

| Setting | Value |
|---------|--------|
| Host | `outlook.office365.com` |
| Port | 993 |
| Security | SSL/TLS |
| Username | `CRSid@cam.ac.uk` |
| Auth | OAuth2 / XOAUTH2 |

### Refresh-token write-back

lynguine CIP-0019 says the plugin should not call `CredentialManager`;
lynguine injects `credential_value`. Token rotation needs a write.

v1 exception, documented here: after a successful refresh that returns
a new `refresh_token`, the plugin calls
`set_credential(key, payload, credential_type="imap")` when
`details["credential"]` is the key. If `set_credential` is unavailable
(old lynguine without CIP-001A persist), keep the in-memory token for
this process and warn once. Do not write tokens to YAML or env.

Do not add a generic OAuth engine to lynguine for this one consumer.

### Out of scope

- `msal` or `microsoft_oauth` in lynguine core
- Changing `lynguine-cred` to talk to Microsoft
- Gmail API / `google_oauth` (still a later `type: gmail`)
- Client-credentials / app-only IMAP (`IMAP.AccessAsApp`)
- Microsoft Graph as a substitute for IMAP
- Message bodies, write-back to the mailbox, IMAP IDLE
- Inferring `xoauth2` from hostname

## Implementation Plan

1. Accept this design (this CIP).
2. Extend `validate_imap` for the two forms; tests for mix/unknown
   `auth`.
3. XOAUTH2 connect + MSAL refresh; LOGIN path unchanged.
4. `python -m lynguine_imap.login` bootstrap → `set_credential`.
5. Optional extra `oauth` (`msal`); Poetry script optional.
6. Mocked tests: XOAUTH2 authenticate payload, refresh, LOGIN
   regression, missing msal message. No network, no tenant.
7. README: Cambridge as an example; Entra public client; CIP-001A
   store.

## Backward Compatibility

- LOGIN credentials without `auth` keep working.
- `type: imap` YAML unchanged.
- New dependency only behind extra `oauth`.
- Needs lynguine CIP-001A for persistent `set_credential` on a laptop
  (install from that tree until released). Env-only `set_credential`
  is not an acceptable store for a refresh token.

## Testing Strategy

- Validator: login form, xoauth2 form, mixed fields, bad `auth`.
- Fake IMAP `authenticate` records the SASL mechanism; assert
  `XOAUTH2` and no `login()` call.
- MSAL refresh stubbed; assert the Bearer token is not logged.
- LOGIN tests from CIP-0001 still pass.
- Bootstrap command: stub MSAL device code + stub `set_credential`;
  assert stored dict has `auth: xoauth2` and no password.
- No sockets, no real Entra tenant, no Cambridge password in CI.
