# CIP-0004: Read a mu query as a message table

> CIPs describe HOW to achieve requirements (WHAT).
> Implements [REQ-0004](../requirements/req0004_mu-query-table.md).
> Keeps [REQ-0003](../requirements/req0003_maildir-message-table.md)
> `type: maildir` as a folder scan that does not require mu.

> Hex numbers are per-repository. This is **this repository's**

## Summary

Register `type: mu`: a read-only header table over a **mu find** query.
Call the operator's `mu` binary (`--format=json2`). Do not run
`mu init` or `mu index`. Do not change `type: maildir`. Same five
REQ-0001 columns.

**Which requirements does this CIP address?** REQ-0004 (primary).
REQ-0001 is the column contract. REQ-0003 stays the filesystem type.

## Motivation

`type: maildir` reads **one** folder by walking `cur/` and `new/` and
keeps `limit` newest files by **mtime**. That is the right dumb store,
and it must keep working without mu.

Retrieval across the OfflineIMAP tree is a different job. Date-ordered
"recent mail", `from:`, `subject:`, and `maildir:/cam/INBOX` are what
mu already indexes. CIP-0003 listed "mu / notmuch indexes as a type"
as out of scope; this CIP takes **mu only**.

Embedding Xapian, or treating mu as a silent fast path inside
`type: maildir`, would make YAML mean two stores and make tests need a
live index. A second type keeps the layering CIP-0003 already drew for
offlineimap.

## Detailed Description

### Layering (do not collapse)

```
IMAP server
    │  offlineimap3 / mbsync     (operator, not this package)
    ▼
~/Maildir/<account>/<folder>     ← store for type: maildir
    │  mu init / mu index        (operator, not this package)
    ▼
mu database (~/.cache/mu)        ← store for type: mu
    │  mu find --format=json2
    ▼
type: mu  →  DataFrame (REQ-0001 columns)
```

This package does **not**: start mu, create the database, index
Maildirs, or send mail. A stale index is an operator problem, as a
stale Maildir is for `type: maildir`.

### YAML

```yaml
plugins:
  - lynguine_maildir

input:
  type: mu
  query: "date:2w AND not flag:trashed"
  limit: 50
  index: message_id
```

| YAML | Required | Notes |
|------|----------|--------|
| `type` | yes | `mu` |
| `query` | yes | Non-empty string. mu-query(7) language. Passed as **one** argv after `--`, not through a shell |
| `limit` | no | Positive int → `mu find --maxnum`. Newest first (`--sortfield=date --reverse`) |
| `muhome` | no | Expand `~`. Maps to `--muhome`. Omit to use mu's default |
| `binary` | no | Path to `mu` if it is not on `PATH`. Expand `~` |
| `body_images` | no | `omit` (default) or `url`. Never inline images |
| `credential` | must be absent | Local index; no CIP-0005 bind |

No `path:` / `folder:`. The index already knows the Maildir root from
`mu init`. Folder restriction belongs in the query
(`maildir:/cam/INBOX`). Error if `path` or `folder` is set (those keys
mean `type: maildir`). Error if `credential` is set.

`register_io_type("mu", read=read_mu)` with no `credential_type`.
Poetry entry point `mu = lynguine_maildir` (same module as `maildir`
and `imap`).

### Invocation

Pinned to **mu 1.14** (Homebrew 1.14.4 is the operator version that
motivated this CIP):

```text
mu find --format=json2 --nocolor --sortfield=date --reverse
    [--maxnum N] [--muhome DIR] -- <query>
```

- `argv` list; `shell=False`.
- `--format=json2` (keys without a `:` prefix; man page still calls
  json2 experimental, but 1.14 ships it). Do not parse `plain` or sexp.
- Missing binary: `FileNotFoundError` → `ValueError` naming `type: mu`
  and the binary path.
- Exit **2** (mu-find: no matches): empty DataFrame with the five
  columns.
- Other non-zero: `ValueError` including stderr (truncated).
- Empty or whitespace `query`: `ValueError` before spawning mu.
- `limit` present but not a positive int: same contract as
  `type: maildir`.

Do not pass `--exec`. Do not follow `--format=links`.

### Column mapping (json2 object → row)

| Column | Source |
|--------|--------|
| `uid` | Basename of `path`, flags stripped with the same helper as `type: maildir` (`:2,…` removed). Not an IMAP UID and not mu's docid |
| `message_id` | `message-id` |
| `subject` | `subject` |
| `from` | First `from` contact as `Name <email>` if name is present, else email. Empty string if missing |
| `date` | Indexed sent date as **ISO 8601 UTC** (`YYYY-MM-DDTHH:MM:SSZ`). mu json2 may give a Unix timestamp or a string; normalise. This is **not** the raw `Date:` header and **not** file mtime |

Allowed extra columns (not required; `strict_columns: false` flows may
keep them): `path` (absolute file), `maildir` (mu's maildir field),
`body` (truncated **markdown** from the file at `path`). Outlook Safe
Links are unwrapped to the target URL. Images default to omitted;
`body_images: url` turns remote `http(s)` images into markdown **links**
(not `![]()`, not `<img>`). `cid:` / `data:` are dropped. Do not add
summary or raw json.

Missing keys become `""`. One json object → one row. Full MIME stays
on disk; `body` is listing extra only.

### What this type is not

- Not a fast path inside `type: maildir`. If mu is absent, `type: mu`
  fails; `type: maildir` is unchanged.
- Not `mu cfind` (contacts are a different grain).
- Not notmuch (`type: notmuch` would be a later CIP).
- Not referia `type: email` drafts.

### Operator setup (documentation only)

```bash
mu init --maildir=~/lawrennd/offlineimap/Maildir
mu index
```

Re-index after OfflineIMAP. This CIP does not run those commands.

## Implementation Plan

3. Register `type: mu`; add Poetry entry point `mu`.
4. Tests with a fake `mu` on `PATH` (json2 fixture). No live database

5. README: `type: mu` next to Maildir; operator `init`/`index`; query
   examples.

## Backward Compatibility

- `type: maildir` and `type: imap` unchanged.
- `type: mu` is new. Flows that do not list it are unaffected.
- Requires the `mu` binary at read time. Not a Python dependency.

## Testing Strategy

- Fake `mu` prints one json2 object; assert five columns, uid from
  path, `from` flattened, date ISO.
- Fake `mu` exits 2 → empty frame, same columns.
- Fake `mu` exits 1 with stderr → error includes stderr.
- `query` missing/empty, `credential:` set, `path:` set → `ValueError`.
- `limit: 0` / non-int → `ValueError`.
- `FileNotFoundError` for binary → `ValueError` naming `mu`.
- Spy argv: `--format=json2`, `--reverse`, `--maxnum`, query after
  `--`, no shell.
- Existing Maildir/IMAP tests still pass.
