## Summary

Rename the package and import from `lynguine-imap` / `lynguine_imap` to
`lynguine-maildir` / `lynguine_maildir`. Register `type: maildir` as a
read-only header table over one Maildir directory (`cur/` and `new/`).
Keep `type: imap` (CIP-0001 / CIP-0002) in the same package. Do not
run a syncer and do not put OAuth on the Maildir path.

**Which requirements does this CIP address?** REQ-0003 (primary).
REQ-0001 remains the live IMAP table contract.

## Motivation

lynguine CIP-0019 sketched this plugin as `lynguine-mail`. This repo
shipped as `lynguine-imap` because v1 was a live IMAP reader.

A common operator pattern is different: **offlineimap** (or mbsync)
synchronises IMAP into `~/Maildir`, optionally with XOAUTH2 for
Exchange Online; **mu** / a MUA then read the local tree. Passwords
and tokens stay with the syncer (`.authinfo.gpg`, M365-IMAP refresh
files, lynguine-cred for live IMAP). Lynguine should read the replica,
not become offlineimap.

The package name should match that store: **Maildir**, not IMAP. Live
IMAP stays a second type for flows that have no replica.

## Detailed Description

### Layering (do not collapse)

```
IMAP server
    │  offlineimap3 / mbsync  (operator, not this package)
    │  XOAUTH2 if the server requires it (CIP-0002 or M365-IMAP)
    ▼
~/Maildir/<account>/<folder>     ← store for type: maildir
    cur/  new/  tmp/
    │
    ▼
type: maildir  →  DataFrame (REQ-0001 columns)
```

Live IMAP is a parallel path, not a prerequisite:

```
IMAP server  →  type: imap (CIP-0001 / CIP-0002)  →  same columns
```

This package does **not**: start offlineimap, obtain Microsoft tokens,
index with mu, or send mail.

### Rename

| Today | After |
|-------|--------|
| Distribution `lynguine-imap` | `lynguine-maildir` |
| Import `lynguine_imap` | `lynguine_maildir` |
| Entry point `imap = lynguine_imap` | `imap` and `maildir` both load `lynguine_maildir` |
| Script `lynguine-imap-login` | `lynguine-maildir-login` (IMAP XOAUTH2 bootstrap unchanged) |

No PyPI release exists yet, so there is no compatibility shim. Import
`lynguine_imap` after this CIP is an error. GitHub / on-disk directory
rename (`lynguine-imap` → `lynguine-maildir`) is an operator step when
the remote exists; the Python names change in this CIP.

YAML plugin list becomes:

```yaml
plugins:
  - lynguine_maildir
```

### `type: maildir`

No `credential:`. Path is the Maildir **folder** (the directory that
contains `cur/`, `new/`, and optionally `tmp/`), not the account root
that holds several folders.

```yaml
input:
  type: maildir
  path: ~/Maildir/fastmail/INBOX
  index: message_id
plugins:
  - lynguine_maildir
```

| YAML | Required | Notes |
|------|----------|--------|
| `type` | yes | `maildir` |
| `path` | yes | Expand `~` only. Must contain `cur` and/or `new` |
| `folder` | alias of `path` | Error if both are set and differ |
| `limit` | no | Positive int; keep the newest files by mtime |
| `body_images` | no | `omit` (default) or `url`. Never inline images |
| `credential` | must be absent | Local files; no CIP-0005 bind |

`register_io_type("maildir", read=..., credential_type=None)`.

### Read contract

- One row per file in `cur/` and `new/`. Skip `tmp/` (delivery in
  progress) and subdirectories.
- Required columns are **headers** (`email.parser.BytesHeaderParser`
  or equivalent): `uid`, `message_id`, `subject`, `from`, `date`.
- Allowed extras (not required): `path` (absolute file) and `body`
  (truncated markdown for listing `display.detail_field`). Outlook
  Safe Links unwrapped. Optional YAML `body_images: omit` (default)
  or `url` (remote images as links, never inline). This is not a
  CIP-0013 document.
- `uid` is the Maildir unique basename with flags stripped (the name
  up to `:2,` if present). This is **not** an IMAP UID. Document that
  in the README.
- Do **not** rename or move files. `new/` stays `new/` (read-only,
  analogue of `BODY.PEEK`).
- Missing `path`, path not a directory, or directory with neither
  `cur/` nor `new/` fails with the path in the message.
- Empty Maildir returns the column frame, no rows.

### `type: imap` after rename

Unchanged behaviour, new import path. CIP-0002 login module moves with
the package. Extra `oauth` (`msal`) stays optional and is unused by
`type: maildir`.

### Out of scope

- Running or configuring offlineimap / mbsync
- Shipping Thunderbird's client id
- Recursing an account root (`~/Maildir/fastmail`) into many folders
- Maildir write-back, flags, or `new/` → `cur/`
- mu / notmuch indexes as a type (mu: [CIP-0004](./cip0004.md))
- SMTP / `type: email` drafts (referia)

## Backward Compatibility

- `import lynguine_imap` breaks (no release to protect).
- YAML `type: imap` still works after `plugins: [lynguine_maildir]`.
- `type: maildir` is new.
- Git clone path and GitHub name change only when the operator
  renames the repository.

## Testing Strategy

- Temporary Maildir: one message in `cur/`, one in `new/`, junk in
  `tmp/`. Assert two rows, `tmp/` ignored, `new/` file still in `new/`.
- MIME-encoded Subject matches CIP-0001 behaviour.
- `path` with `~` expands; non-Maildir directory fails naming the path.
- `write_data` raises read-only.
- Existing IMAP tests import `lynguine_maildir`.
